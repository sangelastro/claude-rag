02 / 10
Motivazione

Perché non caricare i file .md direttamente in contesto

Senza RAG

  • 23 file .md caricati ad ogni query
  • ~50 000 token di contesto occupati
  • Lento, costoso, rumoroso
  • Claude deve cercare manualmente tra tutto
  • Impossibile tenere aggiornato in real-time

Con RAG

  • Solo 5–7 chunk rilevanti per query
  • ~2 000 token di contesto al massimo
  • Risposta immediata e precisa
  • Indice aggiornabile via kb_reindex()
  • Ricerca semantica: nessuna keyword esatta richiesta

Pre-processing

Chunking dei file .md per sezione

# API Reference ## authentication POST /auth/token params: client_id, client_secret response: { access_token } ## orders GET /orders/{id} response: { id, status, items, total } ## webhooks POST /webhooks/register payload: { url, events }
→
[schema_api] API Reference › authentication
POST /auth/token — params: client_id, client_secret ...
[schema_api] API Reference › orders
GET /orders/{id} — response: { id, status, items } ...
[schema_api] API Reference › webhooks
POST /webhooks/register — payload: { url, events } ...

Ogni sezione ## diventa un chunk indipendente. L'header contestuale include nome file, titolo # e titolo sezione — così ogni chunk è auto-esplicativo anche senza contorno.

Embedding — distanza semantica

Similarità coseno — come si misura la vicinanza

Non conta la magnitudine del vettore, solo la direzione. Testi diversi in parole ma vicini in significato producono un angolo piccolo → score alto.

formula
cos(θ) = q · c|q| · |c|

08 / 10
Runtime

Il flusso di una query

01

Chiamata MCP da Claude Code

kb_search("database connection string") arriva via JSON-RPC su stdio.

02

Encoding della query

model.encode([query]) → vettore float32 × 384. Stesso modello usato in fase di indicizzazione, stesso spazio vettoriale.

03

Similarità coseno su tutti i chunk

Tutti i BLOB vengono caricati da SQLite → np.frombuffer(bytes, dtype=float32) → dot(q, c) / (|q|·|c| + ε) per ciascuno dei 242 chunk.

04

Top-K ranking & risposta

I chunk ordinati per score decrescente. I top-K (default 5, max 10) tornano come stringa con [file › sezione] (score: 0.842) + contenuto. Claude riceve solo questi.

09 / 10
Manutenzione

Auto-reindex basato su mtime

All'avvio del server

  • Lista tutti i .md nella cartella KB (escluso MEMORY.md)
  • Per ogni file: confronta mtime attuale con mtime salvata in SQLite
  • Se diversa → cancella vecchi chunk → reindicizza
  • Se uguale → skip, zero lavoro aggiuntivo

Operazioni extra

  • Orphan cleanup: chunk di file eliminati rimossi automaticamente
  • Force reindex: kb_reindex(force=True) reindicizza tutto
  • Post-edit: dopo ogni modifica a un .md, Claude chiama kb_reindex()
  • Limite noto: un semplice touch triggera reindex non necessario

Il server gira come processo persistente per tutta la sessione Claude Code. L'auto-reindex all'avvio garantisce che l'indice sia allineato ai file su disco prima della prima query.
