claude-rag MCP Server

Sistema di Retrieval Augmented Generation per knowledge base in Markdown. Espone una ricerca semantica come tool MCP, permettendo a Claude Code di recuperare solo i chunk rilevanti invece di caricare interi file .md.

Versione 1.0 Data 2026-08-01 Modello embeddings all-MiniLM-L6-v2 Transport MCP stdio Vector store SQLite (float32 blob)
01 — Panoramica

Cos'è e perché esiste

Una KB è un insieme di file .md che documentano accessi, schemi DB, API, procedure operative e architetture dei sistemi. Senza RAG, ogni conversazione deve caricare interi file nel contesto — spesso 5.000–15.000 token per rispondere a una domanda che richiederebbe 200 token di contesto rilevante.

Il RAG risolve questo: indicizza ogni file in chunk semantici per sezione, li codifica come vettori con un modello locale, e al momento della query restituisce solo i chunk più simili (tipicamente 5 × ~300 token = ~1.500 token vs 10.000+).

◈

I file .md non vengono modificati né rimossi — restano leggibili da umani. Il sistema aggiunge solo un indice SQLite (kb.db) nella stessa cartella del server.

02 — Pipeline di indicizzazione

Come vengono processati i file

Fase 1 — Chunking per sezione

Ogni file viene letto e suddiviso usando le intestazioni ## come delimitatori di chunk. Il frontmatter YAML viene rimosso. Ogni chunk include un header contestuale con nome file e sezione. 

[schema_api] API Reference > authentication

POST /auth/token — returns JWT bearer token
  params: client_id, client_secret
  response: { access_token, expires_in }
...

Fase 2 — Embedding

I chunk vengono codificati con sentence-transformers/all-MiniLM-L6-v2, un modello da ~90MB che gira completamente in locale su CPU. Produce vettori a 384 dimensioni.

Fase 3 — Storage in SQLite

CREATE TABLE chunks (
  id        INTEGER PRIMARY KEY,
  file      TEXT     NOT NULL,
  section   TEXT     NOT NULL,
  content   TEXT     NOT NULL,
  embedding BLOB     NOT NULL,   -- float32 × 384 dims
  mtime     REAL     NOT NULL
);

Auto-reindex

Ad ogni avvio del server, reindex_all() confronta l'mtime registrata con quella corrente. Reindicizza solo i file modificati e rimuove chunk di file cancellati (orphan cleanup).

03 — Componenti

Anatomia del server

Modello

SentenceTransformer

Caricato in memoria una volta sola al primo avvio (_model global). Usato sia per indicizzare che per codificare le query.

Storage

SQLite + BLOB

Nessuna dipendenza da librerie vettoriali esterne. Similarità coseno calcolata in Python su numpy.

Server

MCPServer (mcp 2.0)

Classe high-level di mcp.server.mcpserver. Decorator @mcp.tool() per ogni funzione esposta. Transport stdio.

Tools MCP

3 tool esposti

kb_search — ricerca semantica.
kb_reindex — forza reindicizzazione.
kb_stats — statistiche indice.

04 — Integrazione MCP

Come Claude Code lo usa

Il server è registrato nel file ~/.claude.json nella sezione mcpServers. Claude Code avvia il processo con py server.py e comunica via stdio con il protocollo JSON-RPC MCP. 

"kb-rag": {
  "command": "python",
  "args": ["/path/to/claude-rag/server.py"],
  "env": { "KB_RAG_DIR": "/path/to/your/kb/folder" }
}
↻

Dopo ogni modifica a ~/.claude.json o al codice del server, riavviare Claude Code per ricaricare il server MCP.

05 — Lifecycle di una query

Cosa succede quando chiedo qualcosa

  • 01
    Ricezione query
    Claude Code invia al tool kb_search la stringa di ricerca (es. "database connection string postgresql").
  • 02
    Embedding query
    SentenceTransformer.encode(query) produce un vettore float32 × 384. Il modello è già in memoria — tempo tipico <50ms su CPU.
  • 03
    Caricamento chunk
    SQLite restituisce tutti i chunk (242). Ogni embedding BLOB viene deserializzato in numpy array.
  • 04
    Similarità coseno
    Per ogni chunk: score = dot(q, c) / (|q| × |c|). Sorted descending. I top-K (default 5) vengono selezionati.
  • 05
    Risposta formattata
    Il risultato torna a Claude Code come stringa con header [file > sezione], score e contenuto.

Limite del RAG: se la risposta richiede contesto distribuito su molti file contemporaneamente, il RAG è meno efficace. In quei casi, top_k=10 o il caricamento esplicito di un file specifico resta preferibile.

07 — Manutenzione

Aggiornare la KB dopo modifiche

Il sistema è progettato per richiedere zero intervento manuale nella maggior parte dei casi.

  • A
    Modifica un file .md nella KB.
  • B
    Al prossimo riavvio di Claude Code, il server confronta l'mtime e reindicizza automaticamente solo il file modificato.
  • C
    Oppure, nella sessione corrente: chiama il tool kb_reindex per reindicizzare senza riavviare.
